# JAKE // 30 FOR 30

Thirty questions for coding with an AI that knows nothing until you show it something.

Use them against real work. Give ChatGPT the relevant code, error, file, diff, commit, docs or test result. Keep the answer small. Test it. Bring the result back.

1. I want to build `[idea]`. What is the smallest version worth building first?
2. What is the smallest piece I can build and verify next?
3. Here is the code: `[paste/upload]`. What does it do in one sentence?
4. Which line or block should I understand first, and why?
5. What is this code assuming about its input?
6. Here is the code and exact error: `[paste]`. What is your most likely explanation?
7. What is the quickest test of that explanation?
8. That test failed. What is your next hypothesis?
9. What result would prove your diagnosis wrong?
10. What single test would best prove this function behaves correctly?
11. This works. What is the most important reason it could still be fragile?
12. Can this be simpler without changing its behaviour?
13. What would confuse another developer most in this code?
14. I am putting this on GitHub. What should definitely not be committed?
15. Here is my diff: `[paste/upload]`. What behaviour actually changed?
16. Should this diff be one commit or several?
17. What must the README say so a stranger can run this project?
18. What evidence do you need before changing this code safely?
19. ChatGPT wrote this code. What is the fastest independent check I should make?
20. Before suggesting a change, what do you actually know from the material I supplied?
21. Which file should I show you first to understand this repository?
22. What are you assuming that I have not shown you?
23. Can you reproduce the bug from what I supplied, or are you still inferring?
24. What part of this code currently depends on luck?
25. If I change this function, what else should I retest?
26. What acceptance criterion should I write before changing this feature?
27. Which optimisation would be premature right now?
28. What should I measure before trying to make this faster?
29. What is the strongest argument against the solution you just suggested?
30. Which API, library, function or version in your answer have you actually verified rather than assumed?

**Version 30 is yours. Build something.**
